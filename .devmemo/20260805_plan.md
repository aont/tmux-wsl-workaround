## Conclusion

The recommended implementation strategy is to **preserve the original `argv` in a Bash array and perform `getopts` parsing in two stages**.

1. Parse tmux's global options.
2. Determine the subcommand.
3. Only if the subcommand is `new-session`, parse the `new-session` options.
4. Otherwise, pass the original arguments to the real tmux unchanged and `exec` it.
5. For `new-session`, internally add `-d -P -F` to obtain the newly created session ID.
6. If the user did not originally specify `-d`, attach the current terminal to that session.

Avoid using the external `getopt` command, which stringifies and re-evaluates arguments. Instead, use Bash's `getopts` together with arrays so that arguments containing spaces, newlines, wildcards, or quotes are preserved exactly.

---

## 1. Basic Wrapper Contract

The recommended behavior is as follows.

| Input                        | Behavior                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------- |
| `wrapper list-sessions`      | Pass through to the real tmux unchanged.                                          |
| `wrapper new-session ...`    | Apply special handling.                                                           |
| `wrapper new ...`            | Apply special handling.                                                           |
| `wrapper`                    | Treat as an omitted `new-session` and apply special handling.                     |
| `wrapper -L foo`             | Treat as an omitted `new-session` with global options and apply special handling. |
| `wrapper new-s ...`          | Pass through to the real tmux unchanged.                                          |
| `wrapper new-session -A ...` | Pass through to the real tmux unchanged.                                          |

tmux recognizes not only official command names but also the `new` alias and uniquely identifiable command prefixes. Achieving complete compatibility would require duplicating the entire command table, so for maintainability the wrapper should initially recognize only the canonical command names and official aliases.

### No Arguments

Current versions of tmux invoke `default-client-command` when no arguments are given, whose default value is `new-session`. However, this setting is configurable. Therefore, the wrapper should explicitly define one of the following behaviors.

**Recommended:** Define "no arguments always means `new-session`."

This intentionally differs from environments where tmux's `default-client-command` has been customized.

---

## 2. Parsing Global Options

The first `getopts` pass should parse only tmux's global options up to the subcommand.

The implementation only needs to determine:

* How many arguments the global options consume.
* Options such as `-L` and `-S` that must be forwarded to both the inner tmux and the outer `attach-session`.
* Whether any options incompatible with the wrapper's special handling were specified.

Because tmux's global options may change between versions, the wrapper should maintain an option table matching the target tmux version. In the current source, top-level option parsing is implemented with `getopt` in `tmux.c`.

For the initial implementation, the following global options should simply be forwarded to the real tmux without special handling:

* `-c shell-command`
* `-C`, `-CC`
* `-D`
* `-h`
* `-V`
* Unrecognized options.
* Options missing required arguments.

In other words, the wrapper should not attempt to reproduce tmux's error messages; instead, it should let the real tmux handle all error reporting.

---

## 3. Parsing `new-session` Options

The current tmux option definition for `new-session` is:

```text
Ac:dDe:EF:f:n:Ps:t:x:Xy:
```

Options without arguments:

```text
-A -d -D -E -P -X
```

Options with arguments:

```text
-c -e -F -f -n -s -t -x -y
```

After option parsing, tmux accepts:

```text
[shell-command [argument ...]]
```

These remaining arguments should remain untouched as a Bash array and be passed directly to the inner tmux.

At minimum, record the following during parsing:

```text
user_detached   Whether the original -d was specified.
user_print      Whether the original -P was specified.
user_format     The last -F value specified.
user_attach     Whether -A was specified.
client_flags    The last -f value specified.
no_update_env   Whether -E was specified.
```

If multiple `-F` options are given, use the last one, matching tmux's behavior.

### Handling `--`

The following form must continue to work correctly:

```bash
wrapper new-session -- command -x -y
```

The wrapper's internal `-d -P -F` options must be inserted before `--`.

Conceptually:

```text
new-session
original new-session options
internal -d -P -F ...
--
original shell-command and arguments
```

---

## 4. Handling `-F` Output

The following format is simple but fragile:

```bash
-F '#{session_name} '"${user_format}"
```

If either the session name or the user's format contains spaces, splitting on whitespace makes the boundary ambiguous.

Instead, use:

```bash
SEP=$'\x1f'
internal_format="#{session_id}${SEP}${visible_format}"
```

`session_id` is a unique, immutable identifier such as `$1` and can be passed directly to:

```bash
attach-session -t "$session_id"
```

This avoids issues with session-name prefix matching and special characters.

### Matching tmux's Output Behavior

tmux only produces output when `-P` is specified. If `-F` is omitted, its default format is:

```text
#{session_name}:
```

Therefore, `visible_format` should be determined as follows.

| Original Options      | `visible_format`   | Wrapper Prints Output |
| --------------------- | ------------------ | --------------------- |
| `-P -F user_format`   | `user_format`      | Yes                   |
| `-P` only             | `#{session_name}:` | Yes                   |
| `-F user_format` only | Empty string       | No                    |
| Neither               | Empty string       | No                    |

If you intentionally define "`-F` alone also prints output," then the condition should become:

```text
user_print || user_format_specified
```

However, that would intentionally differ from tmux's semantics.

## 5. Use a Temporary File Instead of Command Substitution

The current implementation uses:

```bash
TMUX_SESSION="$(...)"
```

This approach has several drawbacks:

* Trailing newlines are stripped.
* Multi-line user `-F` output cannot be reproduced faithfully.
* Separating the internal session identifier from user-visible output is difficult.
* Preserving stdout from subsequent tmux commands becomes awkward.

Instead, redirect stdout to a temporary file and read the session ID with `read -d` using the separator.

Conceptually:

```bash
tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT

"$CMD" /c start "" /wait /min \
  wsl.exe -d "$WSL_DISTRO_NAME" \
  --cd "$start_dir" \
  "$TMUX_BIN" \
  "${global_args[@]}" \
  new-session \
  "${new_session_options[@]}" \
  -d -P -F "$internal_format" \
  "${new_session_tail[@]}" \
  >"$tmp"

status=$?

if (( status != 0 )); then
    cat "$tmp"
    exit "$status"
fi

exec {output_fd}<"$tmp"

IFS= read -r -d "$SEP" session_id <&"$output_fd" || {
    printf 'tmux wrapper: session ID was not returned\n' >&2
    exit 1
}

if [[ ! $session_id =~ ^\$[0-9]+$ ]]; then
    printf 'tmux wrapper: invalid session ID: %q\n' "$session_id" >&2
    exit 1
fi
```

If the user originally specified `-P`, copy the remainder of the file descriptor directly to stdout.

Otherwise, discard the remaining line containing the internal format.

## 6. Attach Behavior

The inner tmux should always receive `-d`.

Subsequent behavior depends on whether the user originally specified `-d`.

```text
Original -d present:
    Create the session and exit. Do not attach.

Original -d absent:
    Attach the current terminal using attach-session.
```

This preserves the original meaning of `-d`.

Always attach by session ID rather than by session name.

```bash
exec "$TMUX_BIN" \
  "${attach_global_args[@]}" \
  attach-session \
  "${attach_options[@]}" \
  -t "$session_id"
```

If `new-session -f flags` was specified, the inner tmux is forcibly detached, so the client flags must be forwarded to the outer `attach-session -f`. Likewise, if the user specified `-E`, it should also be propagated to the outer attach operation.

---

## 7. Handle `-A` Separately

`new-session -A` changes behavior when the target session already exists, effectively becoming `attach-session`. In this case, `-D` corresponds to `attach-session -d` rather than `new-session -d`.

Simply adding an internal `-d` can therefore cause the inner `wsl.exe` process to attach to an existing session and block indefinitely.

For the initial implementation, choose one of these policies:

```text
If -A is present, pass everything through to the real tmux unchanged.
```

or

```text
Explicitly reject -A with an error.
```

The former is recommended.

Supporting `-A` fully would require additional logic:

1. Extract the target session from `-s` or equivalent.
2. Execute `has-session` using the same `-L`/`-S` options.
3. If the session exists, attach directly from the outer wrapper.
4. Otherwise, perform the normal detached creation flow.

---

## 8. Command Sequences

tmux supports command sequences such as:

```bash
tmux new-session -d \; split-window \; attach-session
```

If a later command includes `attach-session`, the minimized inner process may attach and block.

For the initial implementation, if a standalone tmux command separator (`;`) appears in the argument list, bypass all special handling and pass the command directly to the real tmux. Only treat `;` as a tmux command separator, not semicolons embedded inside quoted shell commands.

## 9. Issues in the Current Code

The following code passes `$PWD` after changing into `/mnt/c`, so `--cd` always becomes `/mnt/c`.

```bash
cd /mnt/c || exit 1

...
--cd "$PWD"
```

To preserve the caller's working directory:

```bash
start_dir=$PWD

cd /mnt/c || exit 1

"$CMD" /c start "" /wait /min \
  wsl.exe -d "$WSL_DISTRO_NAME" \
  --cd "$start_dir" \
  ...
```

If the wrapper itself is installed as `tmux`, specify the real tmux binary with an absolute path to avoid recursion.

```bash
TMUX_BIN=/usr/bin/tmux
```

Use the same absolute path for the tmux instance launched inside `wsl.exe`.

## 10. Scope of the Initial Implementation

The first version should support the following.

### Supported

* `new-session`
* `new`
* No subcommand
* All short `new-session` options
* Combined short options
* Both `-Fvalue` and `-F value`
* Multiple `-F` options
* `--`
* Any number of `shell-command` arguments
* Preserving `-d`
* Preserving `-P`/`-F` output
* Socket options such as `-L` and `-S`
* Output passing through Windows, including CRLF

### Passed Through Unchanged

* `-A`
* tmux command sequences
* `-C`, `-CC`
* `-D`
* `-c shell-command`
* Abbreviated command names such as `new-s`
* Invalid or unknown options

Finally, note that forcing detached session creation changes how the initial window size is determined. Normally, an attached session uses the client TTY size, whereas a detached session uses `default-size` or explicit `-x`/`-y` values. If exact behavioral compatibility is required, the outer wrapper should obtain the terminal size and supply `-x` and `-y` when appropriate.

Within this scope, the wrapper can preserve argument transparency while safely creating `new-session` instances through Windows and attaching from the outer process.
