## Assessment

The current wrapper already separates the internal session ID from user-visible `-P/-F` output using `#{session_id}`, an ASCII unit separator, and a file descriptor. The transport is currently a regular temporary file populated by `cmd.exe /c start /wait`; the resulting stream is then parsed and the session ID is used for the outer `attach-session`.

The proposed FIFO should replace that transport mechanism without changing argument parsing, `-P/-F` behavior, detach semantics, or attachment by session ID.

## Implementation plan

### 1. Limit the change to the result-transport section

Leave these areas unchanged:

* Global and `new-session` option parsing.
* Construction of `visible_format` and `internal_format`.
* Handling of `-d`, `-E`, `-f`, `-L`, and `-S`.
* Final `attach-session -t "$session_id"` logic.
* The recently added `wsl.exe --exec` behavior.

The primary affected region starts where `tmp` is created and ends after the session output is consumed.

### 2. Allocate a private FIFO safely

Replace the regular temporary file with a private temporary directory containing a result FIFO.

Recommended structure:

```text
temporary directory
└── result.fifo
```

Use `mktemp -d` rather than a predictable `/root/tmux-result-$$-$RANDOM.fifo` name. This avoids:

* Depending on `$RANDOM`, which is not part of portable `ash` syntax.
* Collisions between concurrent wrapper invocations.
* An attacker or stale process pre-creating the FIFO path.

Extend the existing cleanup trap so it removes the FIFO and directory on `EXIT`, `HUP`, `INT`, and `TERM`. The repository explicitly targets `ash`, so the implementation should continue avoiding Bash arrays and other Bash-only constructs.

### 3. Move redirection into the target WSL instance

The important property of the supplied example is that:

```sh
> "$fifo"
```

is evaluated by `/bin/sh` inside the target WSL distribution, rather than by the outer wrapper around `cmd.exe`.

After `wsl.exe ... --exec`, invoke an inner `/bin/sh -c` helper. Pass the FIFO path and tmux arguments as positional parameters rather than interpolating the entire command into shell source.

Conceptually:

```text
/bin/sh -c <fixed helper program> <shell-name> <fifo> <tmux argv...>
```

The helper should execute the tmux command with stdout redirected to the FIFO.

This preserves the current quoting model and reduces the additional nested-shell quoting to a small, fixed script.

### 4. Remove `/wait` from `cmd.exe start`

The FIFO design is incompatible with the current `/wait` arrangement:

1. The inner shell attempts to open the FIFO for writing.
2. Opening blocks until a reader connects.
3. With `/wait`, the outer wrapper waits for the inner process to finish.
4. The outer wrapper never reaches its FIFO read.
5. Both sides deadlock.

Therefore, launch the minimized WSL process asynchronously, as in the supplied example:

```text
cmd.exe /c start "" /min wsl.exe ...
```

Check the immediate `cmd.exe` status, but do not treat it as the final tmux exit status: it only indicates whether the asynchronous launch request was accepted.

Continue using the existing `CMD_EXE`, `WSL_DISTRO_NAME`, `start_dir`, and `TMUX_BIN` values. Do not hardcode the distribution name `tmux`, working directory `/root`, or executable path beyond the wrapper’s existing defaults.

### 5. Open the FIFO once and parse the existing protocol

Open the FIFO on a dedicated file descriptor after initiating the Windows launch:

```text
FD 3 → result FIFO
```

Continue using the existing output protocol:

```text
#{session_id}<SEP><visible output>
```

Processing should be:

1. Read through `SEP` into `session_id`.
2. Validate that a plausible tmux session ID was received.
3. Consume the remainder of the FIFO to EOF.
4. Send that remainder to stdout only when the original command used `-P`.
5. Otherwise drain it to `/dev/null`.
6. Close the descriptor before attaching.

Draining the stream even when `-P` was not requested prevents the producer from being left blocked and ensures that the FIFO reaches EOF cleanly.

### 6. Do not copy `2>&1` directly

The example merges stderr into the FIFO:

```sh
> "$fifo" 2>&1
```

That is unsafe for the full wrapper. A tmux or shell error could become the first data read and be mistaken for `session_id`.

For the repository implementation:

* Redirect only tmux stdout into the result FIFO.
* Leave stderr connected to the wrapper’s stderr.
* Report “session ID was not returned” only after considering the inner command’s status.

### 7. Preserve the inner exit status separately

Removing `/wait` means the existing `status=$?` no longer represents tmux’s exit status.

The robust design is to use a second FIFO:

```text
temporary directory
├── result.fifo
└── status.fifo
```

The inner shell should:

1. Run tmux with stdout directed to `result.fifo`.
2. Capture `$?`.
3. Write the numeric status to `status.fifo`.
4. Exit with that status.

The outer wrapper should:

1. Consume the result FIFO.
2. Read the status FIFO.
3. Return the original tmux status when session creation failed.
4. Only validate and use `session_id` when the status is zero.

This avoids degrading the current error propagation.

### 8. Prevent an indefinite wait

A plain FIFO read can block forever when:

* The configured WSL distribution does not exist.
* `wsl.exe` fails before starting `/bin/sh`.
* The FIFO is created in one distribution but the inner process starts in another.
* The Windows launch succeeds initially but the WSL process never reaches the helper.

Add a bounded launch watchdog or equivalent failure sentinel. In particular, the special FIFO path requires the inner WSL instance to be the same distribution in which the wrapper created the FIFO. For special handling, `WSL_DISTRO_NAME` should therefore be present and passed explicitly; silently using a different default distribution is not safe.

### 9. Preserve attachment behavior

After a successful result:

* Original `-d`: exit without attaching.
* No original `-d`: attach using the returned immutable session ID.
* Preserve outer `attach-session -E` and `-f`.
* Preserve `-L` and `-S` socket selection.

This portion should not require redesign because the current wrapper already targets the returned session ID.

## Acceptance checks

The eventual implementation should be manually checked against:

| Scenario                               | Expected result                              |
| -------------------------------------- | -------------------------------------------- |
| `tmux`                                 | Session ID received; outer client attaches   |
| `tmux new-session -d`                  | Session created; no attachment               |
| `tmux new-session -P`                  | Default printable format preserved           |
| `tmux new-session -P -F ...`           | Exact requested output preserved             |
| `tmux new-session -F ...` without `-P` | No visible output                            |
| `-L` and `-S`                          | Creation and attachment use the same server  |
| Invalid tmux arguments                 | Original nonzero status; no hang             |
| Invalid WSL distribution               | Bounded failure; no permanent FIFO wait      |
| Two simultaneous invocations           | Independent FIFO paths and session IDs       |
| Interrupt during launch                | FIFOs and temporary directory removed        |
| Arguments containing spaces or quotes  | Inner tmux receives the original argv        |
| `-A` or command sequences              | Existing passthrough behavior remains intact |

The repository currently contains the wrapper, its design memo, and license, but no test harness, so this can initially be verified with a documented command matrix rather than adding unrelated infrastructure.

No files, branches, commits, pull requests, or repository settings were changed.
